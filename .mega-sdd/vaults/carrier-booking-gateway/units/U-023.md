# Unit U-023 — Implement the Evergreen (EGLV) carrier adapter

## Goal

Implement the Evergreen adapter with signed-JWT auth and mapping for Evergreen ShipmentLink's proprietary (non-DCSA) payloads, plus a contract test against the Evergreen mock. Record the mandatory IP-allowlist dependency.

## Context (read first)

Per spec §10 and decision D-015, Evergreen (SCAC `EGLV`) authenticates with a signed JWT and requires the caller's egress IP to be on its allowlist (the static IP is available; it must be registered during onboarding). Payloads are proprietary, so the mapping is best-effort against the provisional Evergreen mock and will change after sandbox access. Quirks stay inside this folder; the adapter never touches the DB.

## Anchors

- packages/carrier-core/src/auth/jwtBearer.ts — makeJwtBearer
- packages/carrier-core/src/adapter.ts — CarrierAdapter surface
- apps/mock-carriers — the Evergreen namespace (added here or in U-019) is the contract to code against

## Hard rules

- NEVER import from apps/booking/src/db or issue SQL in apps/booking/src/adapters/evergreen (constitution C-001)
- NEVER let an Evergreen status string cross the adapter boundary; only toCanonicalStatus output does (spec §5)
- ALWAYS isolate the proprietary-shape mapping in mapRequest.ts / mapStatus.ts so it can be replaced after sandbox access
- file:apps/booking/src/adapters/evergreen/*.ts MUST follow camelCase naming

## Implementation steps

1. Add or finalize the Evergreen namespace in `apps/mock-carriers` reflecting the provisional proprietary shape.
2. Write `mapRequest.ts` (canonical → Evergreen payload) and `mapStatus.ts` (`toCanonicalStatus`) covering every status the Evergreen mock emits.
3. Write `mapTracking.ts` → `NormalizedEvent[]` with a stable `dedupeKey`.
4. Write `index.ts` implementing `CarrierAdapter` (`code: 'EGLV'`, `transport: 'REST'`) with the JWT-bearer strategy and error classification.
5. Write `evergreen.contract.test.ts` running `runContractSuite` against the Evergreen mock.
6. Add `README.md` recording the JWT signing requirement, the mandatory IP allowlist (must register the static egress IP with Evergreen), and sandbox open questions.
