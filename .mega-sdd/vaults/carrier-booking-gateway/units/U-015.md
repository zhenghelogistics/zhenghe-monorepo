# Unit U-015 — Build packages/auth (session/JWT verify + RBAC middleware)

## Goal

Provide the thin auth package: verify a session / JWT into a `{ userId, role }` principal, and a Fastify middleware that gates a route by required role (`admin` / `controller` / `viewer`).

## Context (read first)

Per spec §7 and §15, the internal API has three roles and all permission checks are server-side; the frontend guard is cosmetic. This package is deliberately small — spec §15 says "local users mirroring the Greenlit plan". It exposes `verifyRequest(req) -> Principal` and `requireRole(...roles)` as a Fastify preHandler; the actual user store and login endpoint are left to the API unit / a later auth-hardening pass.

## Hard rules

- ALWAYS enforce requireRole server-side: 401 when unauthenticated, 403 when the role is insufficient (constitution B-004)
- DO NOT import from apps/booking in packages/auth
- file:packages/auth/src/*.ts MUST follow camelCase naming

## Implementation steps

1. Create `packages/auth/package.json` (name `@zhenghe/auth`) depending on a JWT verify lib and Fastify types.
2. Write `session.ts` with `Principal = { userId: string; role: Role }`, `Role = 'admin' | 'controller' | 'viewer'`, and `verifyToken(token, secret) -> Principal` plus `verifyRequest(req, secret)` that reads the bearer / cookie.
3. Write `rbac.ts` with `requireRole(...allowed: Role[])` returning a Fastify preHandler that calls `verifyRequest`, 401s on failure, 403s when `principal.role` is not in `allowed`, and attaches `req.principal`.
4. Write `rbac.test.ts`: no token -> 401; `viewer` hitting a `controller` route -> 403; `admin` allowed everywhere.
