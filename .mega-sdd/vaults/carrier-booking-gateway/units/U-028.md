# Unit U-028 — Build the Carriers / settings admin screen

## Goal

Implement the admin-only Carriers / settings screen: the carrier registry with capability flags and credential health, plus a form to set or rotate a carrier credential.

## Context (read first)

Per spec §15 and flow F-U-003. The screen lists each carrier from `GET /carriers` with `transportMode`, `capabilities`, `enabled`, and `credential: { configured, lastAuthOk, circuitState }`, never showing secret material. The credential form submits `{ authType, secret, baseUrl, accountRef? }` to `PUT /carriers/:code/credentials`, which is `admin`-only server-side; the screen itself is also gated by the `admin` role in the guard.

## Anchors

- apps/booking/web/src/lib/apiClient.ts — listCarriers, putCarrierCredential
- apps/booking/web/src/lib/authGuard.tsx — the admin gate
- flows.md#F-U-003 — the set/rotate credential flow and its DoD

## Hard rules

- ALWAYS gate the screen and its route by the `admin` role (constitution B-004)
- NEVER display a secret value or echo an entered secret back after submit
- file:apps/booking/web/src/**/*.tsx MUST follow PascalCase naming for component files

## Implementation steps

1. Write `components/CredentialForm.tsx` — fields switch on `authType` (`oauth2`: tokenUrl/clientId/clientSecret/scope + optional extra headers; `api_key`: headerName/value; `jwt`: signingKey/algorithm/claims/ttl), plus `baseUrl` and optional `accountRef`; on submit calls `putCarrierCredential(code, body)` and clears the secret fields.
2. Write `screens/Carriers.tsx` — a table of carriers from `listCarriers()` with capability badges, `enabled` state, and a credential-health cell (`configured` / `lastAuthOk` / `circuitState`); each row expands to the `CredentialForm`.
3. Write `screens/carriers.test.tsx` — with a mocked client: the table renders health without any secret field; submitting the form calls `putCarrierCredential` and refetches; rendering with a `controller` principal shows an access-denied state.

## Acceptance criteria

Acceptance criteria are the frontmatter `acceptance_test:` entries (authoritative).

## Out of scope

- Server-side credential storage and encryption (U-010).
- The `/carriers` route implementation (U-017).
