# Unit U-008 — Implement carrier-core auth strategies (OAuth2 client-credentials, API key, JWT bearer)

## Goal

Provide the three `AuthStrategy` implementations the four v1 carriers need: OAuth2 client-credentials with token caching, a static API-key header, and a signed JWT bearer with expiry-based caching.

## Context (read first)

Per spec §8 and §10: Maersk uses OAuth2 client-credentials plus an extra static `Consumer-Key` header, ONE and HMM use an API key header, Evergreen signs a JWT. Each strategy exposes `apply(requestInit)` that the `HttpClient` (U-007) calls before sending, and a way to force-refresh on a 401. Token/JWT caches live in-memory keyed by carrier + account.

## Anchors

- packages/carrier-core/src/http/client.ts — the AuthStrategy contract and where apply() is invoked

## Hard rules

- NEVER log a token, client secret, API key, or JWT signing key (constitution B-002)
- ALWAYS let oauth2ClientCredentials accept an optional map of extra static headers (Maersk Consumer-Key)
- file:packages/carrier-core/src/auth/*.ts MUST follow camelCase naming

## Implementation steps

1. Write `oauth2ClientCredentials.ts`: given `{ tokenUrl, clientId, clientSecret, scope?, extraHeaders? }`, fetch and cache the token with its `expires_in`, refresh a configurable margin before expiry, expose `apply()` that sets `Authorization: Bearer` plus any `extraHeaders`, and `invalidate()`.
2. Write `apiKeyHeader.ts`: given `{ headerName, value }`, `apply()` sets that header; `invalidate()` is a no-op.
3. Write `jwtBearer.ts`: given `{ signingKey, algorithm, claims, ttlSeconds }`, mint and cache a signed JWT, refresh before `ttlSeconds` elapses, `apply()` sets `Authorization: Bearer <jwt>`.
4. Write `index.ts` exporting a `makeAuthStrategy(authType, secret)` factory keyed by the `auth_type` values in `model.md` (`oauth2` / `api_key` / `jwt`).
5. Write `auth.test.ts`: token cached and reused until near expiry then refreshed; `invalidate()` forces a new fetch; the API-key strategy sets the configured header; the JWT strategy produces a verifiable token.
