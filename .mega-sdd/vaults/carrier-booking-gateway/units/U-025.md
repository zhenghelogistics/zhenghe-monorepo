# Unit U-025 — Scaffold the apps/booking/web frontend (Vite + React 19 shell, auth guard, API client)

## Goal

Stand up the thin operator UI: a Vite + React 19 + TypeScript app with TanStack Query, an app shell with navigation, a role-aware route guard, and a typed API client against the internal API.

## Context (read first)

Per spec §15, the frontend is deliberately thin and has no business logic — it renders `status` from the API and never derives it. Motus shell patterns are copied and adapted, not imported. This unit ships the shell and plumbing only; the four screens land in U-026..U-028. The API client wraps `fetch` with the bearer token, base URL from env, and typed helpers per route group.

## Anchors

- apps/booking/src/api/bookings.ts — route shapes the client mirrors
- apps/booking/src/api/carriers.ts — /carriers shape for the admin screen client
- packages/auth/src/session.ts — the Role type the guard checks against

## Hard rules

- NEVER compute or derive booking status in the frontend; render the API value verbatim (constitution C-003)
- DO NOT import from apps/booking/src (server code) in apps/booking/web; use HTTP only
- file:apps/booking/web/src/**/*.tsx MUST follow PascalCase naming for component files

## Implementation steps

1. Create `apps/booking/web/package.json` (name `@zhenghe/booking-web`) with Vite, React 19, TypeScript, and TanStack Query; add `dev`, `build`, `test` scripts.
2. Write `index.html` + `src/main.tsx` mounting `<AppShell/>` inside a `QueryClientProvider`.
3. Write `src/app/AppShell.tsx` with the top nav (Bookings, New booking, Carriers — the last only for `admin`) and a routed `<Outlet/>`.
4. Write `src/lib/apiClient.ts` exporting typed functions per route group (`listBookings`, `getBooking`, `createBooking`, `cancelBooking`, `refreshBooking`, `getBookingEvents`, `getBookingTracking`, `listCarriers`, `putCarrierCredential`, `queryTracking`), each attaching the bearer token and parsing JSON.
5. Write `src/lib/authGuard.tsx` — a component that reads the current principal, redirects to a minimal login when absent, and hides/disables routes above the user's role.
