# Unit U-018 — API integration test suite (roles, idempotency, validation, health) with FakeAdapter

## Goal

Boot the real Fastify server against a real Postgres with the `FakeAdapter` registry and exercise the full API surface: RBAC roles, `Idempotency-Key`, zod validation errors, the create→confirm→cancel path over HTTP, and `/health`.

## Context (read first)

Per spec §12, this is the API-level counterpart to U-014's domain-level lifecycle test. `test/support/app.ts` composes `buildServer` with real domain services, the test DB, and a registry containing one `FakeAdapter` per carrier code so no network is touched. The suite asserts the documented status codes and that a booking created via `POST /bookings` reaches `CONFIRMED` after the worker runs, then cancels.

## Anchors

- apps/booking/src/server.ts — buildServer
- apps/booking/test/fakeAdapter.ts — FakeAdapter
- apps/booking/test/support/db.ts — test DB helpers from U-014
- apps/booking/src/worker/tasks.ts — tasks driven inline between assertions

## Hard rules

- NEVER make a real network call to a carrier host from the suite
- ALWAYS assert a `viewer` token is rejected (403) on every mutating route
- file apps/booking/test/api.integration.test.ts MUST exist after bolt

## Implementation steps

1. Write `support/app.ts` exporting `buildTestApp()` that wires `buildServer` with real services, the test pool, and a registry of `FakeAdapter`s, plus a helper to run a named worker task once.
2. Write `api.integration.test.ts`: `POST /bookings` as `controller` → 202; run `submitBooking` + loop `pollBookingStatus` → `GET /bookings/:id` shows `CONFIRMED`; `POST /bookings/:id/cancel` → 202, run `submitCancellation` → status `CANCELLED`; `GET /bookings/:id/events` returns the ordered timeline; `GET /bookings/:id/tracking` returns events after confirm.
3. Add negative cases: missing token → 401; `viewer` on create/cancel/refresh/credentials → 403; malformed create body → 400; duplicate `Idempotency-Key` → same `bookingId`, one row.
4. Add `GET /health` returns 200 with `db`, `worker`, `carriers` populated.
