# Unit U-003 — Build packages/db (pg pool + migration runner + base types)

## Goal

Create the shared `packages/db` package: a `pg` connection pool factory, a thin wrapper around `node-pg-migrate` for running SQL migrations up/down, and shared row/column TypeScript types.

## Context (read first)

Runs after U-001. Per spec §4/§6, all database access in the project is hand-written SQL via `pg` with `node-pg-migrate` for schema changes — no ORM. This package is the single place that owns the pool and the migration entrypoint; `apps/booking` and any future app import it. It ships no schema of its own — the booking schema lands in U-004 under `apps/booking/src/db/migrations`.

## Hard rules

- DO NOT add an ORM or query-builder dependency (constitution A-002)
- NEVER read the connection string from process.env in packages/db; take it as an injected argument
- file:packages/db/src/*.ts MUST follow camelCase naming

## Implementation steps

1. Create `packages/db/package.json` (name `@zhenghe/db`) depending on `pg` and `node-pg-migrate`.
2. Write `src/pool.ts` exporting `createPool(connectionString: string)` returning a configured `pg.Pool` with sane defaults (max connections, idle timeout) and a `withClient` helper for transactions.
3. Write `src/migrate.ts` exporting `runMigrations(dir: string, direction: 'up' | 'down', connectionString: string)` that shells to `node-pg-migrate` programmatically against the given migrations directory.
4. Write `src/types.ts` with the small shared primitives used across queries (a `Uuid` brand, a `Jsonb<T>` helper, a `Timestamptz` alias) — not the per-table row types, which live with `apps/booking`.
5. Add a smoke test that spins the pool against a `DATABASE_URL` and runs a trivial `SELECT 1`.

## Acceptance criteria

Acceptance criteria are the frontmatter `acceptance_test:` entries (authoritative).

## Out of scope

- The actual booking schema and migrations (U-004).
- graphile-worker installation (U-004).
- Any query module for a specific table (units in M-gateway-domain / M-api).
