# Unit U-026 — Build the Bookings list and New booking screens

## Goal

Implement the default Bookings list (table + filters + pagination) and the New booking form for the canonical booking request, with client-side validation mirroring the server schema.

## Context (read first)

Per spec §15 and flow F-U-001. The list table shows carrier, booking ref, POL→POD, vessel/voyage, requested ETD, a status chip, and updated; filters are status / carrier / date range / customer ref. The New booking form covers the canonical request with repeatable commodity and equipment rows, carrier select limited to `enabled` + `configured` carriers from `GET /carriers`, and it validates with the carrier-core zod schema before `POST /bookings`, then redirects to the detail screen on the `202`.

## Anchors

- apps/booking/web/src/lib/apiClient.ts — listBookings, createBooking, listCarriers
- packages/carrier-core/src/schemas.ts — canonicalBookingRequestSchema for form validation
- flows.md#F-U-001 — the create flow and its DoD

## Hard rules

- NEVER derive the status chip value client-side; render the API `status` (constitution C-003)
- ALWAYS validate the form with canonicalBookingRequestSchema before calling createBooking (constitution A-003)
- DO NOT render commodities and equipment as a single flat field set; use repeatable input groups (constitution D-002)
- file:apps/booking/web/src/**/*.tsx MUST follow PascalCase naming for component files

## Implementation steps

1. Write `components/BookingForm.tsx` — a controlled form for `CanonicalBookingRequest` with add/remove rows for commodities and requestedEquipments, a carrier `<select>` populated from `listCarriers()` filtered to `enabled && credential.configured`, and inline errors from a `safeParse` against the schema.
2. Write `screens/NewBooking.tsx` — renders `BookingForm`, on submit calls `createBooking(payload, idempotencyKey)` (generate a client UUID for the key), and navigates to `/bookings/:id` on success.
3. Write `screens/BookingsList.tsx` — a TanStack Query table over `listBookings(filters)` with the documented columns, a filter bar (status / carrier / date range / customer ref), and pagination controls driven by the API `{ page, pageSize, total }`.
4. Write `screens/bookings.test.tsx` — render the list with a mocked client and assert rows + filter query params; render the form, submit invalid data and assert errors, submit valid data and assert `createBooking` is called and navigation happens.
