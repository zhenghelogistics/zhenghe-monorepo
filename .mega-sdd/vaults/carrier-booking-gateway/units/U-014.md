# Unit U-014 — FakeAdapter fixture + full booking-lifecycle test against real Postgres

## Goal

Provide a reusable `FakeAdapter` and an end-to-end domain test that drives a booking from create through poll, confirm, and cancel against a real Postgres, asserting the final `bookings`, `booking_events`, and `shipment_events` state.

## Context (read first)

Per spec §12, this is the domain-lifecycle test that proves the choke point, the worker tasks, and the credential/context wiring hang together before any real adapter exists. `FakeAdapter` implements `CarrierAdapter` with an in-memory scripted status progression and tracking list, and it must also pass `runContractSuite` (U-009) so it is a faithful stand-in. `test/support/db.ts` owns test-database setup/teardown (migrate up, truncate between tests).

## Anchors

- packages/carrier-core/src/testing/contractKit.ts — runContractSuite the FakeAdapter must satisfy
- apps/booking/src/worker/tasks.ts — the tasks the lifecycle test exercises
- apps/booking/src/domain/statusReconciler.ts — the state machine being verified

## Hard rules

- NEVER touch the database from FakeAdapter (constitution C-001)
- ALWAYS assert booking_events seq is contiguous and every status change source is adapter / poller / user
- file apps/booking/test/fakeAdapter.ts MUST exist after bolt

## Implementation steps

1. Write `support/db.ts` with `withTestDb()` helpers: run migrations up once, `TRUNCATE ... RESTART IDENTITY CASCADE` between tests, expose a pool.
2. Write `fakeAdapter.ts`: a `CarrierAdapter` whose `createBooking` returns an ack + fake ref, `getBookingStatus` walks `RECEIVED -> PENDING_CONFIRMATION -> CONFIRMED` on successive calls (or by elapsed calls), `getTracking` returns a scripted `NormalizedEvent[]`, `cancelBooking` flips an internal flag, `toCanonicalStatus` maps its raw strings; add a `scenario` knob to force `VALIDATION` / `CARRIER_UNAVAILABLE`.
3. Write `lifecycle.test.ts`: register `FakeAdapter` in the registry; call `bookingService.createBooking`; run the worker `submitBooking` then loop `pollBookingStatus` until `CONFIRMED`; run `pollTracking` and assert `shipment_events` rows; call `requestCancel` + `submitCancellation` and assert `CANCELLED`; assert the full `booking_events` timeline.
4. Add a test that `runContractSuite(new FakeAdapter())` passes.
