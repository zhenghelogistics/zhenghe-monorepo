# Unit U-004 — Write the booking schema migrations + carrier seed + graphile-worker install

## Goal

Create the SQL migrations for all seven tables in `model.md`, seed the `carriers` table with the four v1 carriers, install `graphile-worker`'s tables, and provide TypeScript row types.

## Context (read first)

Runs after U-002 (app package) and U-003 (`packages/db`). This is a direct transcription of `model.md ## Entities` — `carriers`, `carrier_credentials`, `bookings`, `booking_events`, `shipment_events`, `carrier_messages`, `credential_events` — with every unique index and secondary index listed in `model.md ## Constraints`, including the two partial unique indexes (`carrier_credentials(carrier_code) WHERE is_active`, `bookings(created_by, idempotency_key) WHERE idempotency_key IS NOT NULL`). The migration must be reversible. graphile-worker owns its own tables via its installer SQL.

## Anchors

- packages/db/src/migrate.ts — the runMigrations wrapper this unit's test drives
- packages/db/src/types.ts — reuse Uuid / Jsonb / Timestamptz helpers in rowTypes.ts

## Hard rules

- DO NOT add an ORM or query-builder dependency (constitution A-002)
- file apps/booking/src/db/migrations/001_core_schema.sql MUST exist after bolt
- DO NOT define ON DELETE CASCADE that hard-deletes operational rows; use soft delete / archive (constitution F-003)
- ALWAYS declare timestamp columns as timestamptz (constitution F-004)

## Implementation steps

1. Write `001_core_schema.sql` creating the seven tables exactly as `model.md` specifies — column names, types, nullability, the `jsonb` columns, and all indexes including the two partial unique indexes; provide a matching `down` that drops them in FK-safe order.
2. Write `002_graphile_worker.sql` that runs the graphile-worker schema installer (or document the runtime `installSchema` call if the library version installs on boot) so the queue tables exist before U-013.
3. Write `seed/carriers.sql` inserting the four rows: `ONEY` / `MAEU` / `HDMU` / `EGLV` with `transport_mode = 'REST'`, `dcsa_booking_version` per `model.md` (`2.0.0` for ONE/Maersk, `null` for HMM/Evergreen), `capabilities` jsonb, `enabled = true`.
4. Write `rowTypes.ts` exporting one TypeScript type per table mirroring the columns, using the `packages/db` primitives; export a `CanonicalBookingStatus` string-union matching the enum note on `bookings.status`.
5. Write `migrate.test.ts` that migrates up against a test `DATABASE_URL`, asserts the seven tables and the partial unique indexes exist, migrates down, and asserts they are gone.
