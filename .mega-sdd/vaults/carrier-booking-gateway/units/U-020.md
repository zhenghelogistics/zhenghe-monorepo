# Unit U-020 — Implement the ONE (ONEY) carrier adapter

## Goal

Implement the ONE adapter: canonical→ONE payload mapping, ONE status→canonical mapping, ONE events→`NormalizedEvent[]`, API-key auth, and a contract test that passes `runContractSuite` against the ONE mock.

## Context (read first)

Per spec §10, ONE (SCAC `ONEY`) uses an API-key header and its booking + Track & Trace are reasonably close to DCSA Booking 2.0, so the mapping is largely field renames. The adapter is transport-agnostic per the interface (U-006) and never touches the DB. All carrier quirks (rate limits, header name) stay inside this folder. The `README.md` records open questions to resolve when the ONE sandbox is granted.

## Anchors

- packages/carrier-core/src/adapter.ts — CarrierAdapter surface
- packages/carrier-core/src/auth/index.ts — makeAuthStrategy('api_key', ...)
- packages/carrier-core/src/schemas.ts — canonical shapes the maps translate to/from
- apps/mock-carriers/src/carriers/one.ts — the mock contract to code against

## Hard rules

- NEVER import from apps/booking/src/db or issue SQL in apps/booking/src/adapters/one (constitution C-001)
- NEVER let a ONE status string cross the adapter boundary; only toCanonicalStatus output does (constitution D-001 / spec §5)
- file:apps/booking/src/adapters/one/*.ts MUST follow camelCase naming

## Implementation steps

1. Write `mapRequest.ts` translating `CanonicalBookingRequest` to the ONE booking payload (parties, commodities, equipment, transport, references), handling ISO/UN-LOCODE fields.
2. Write `mapStatus.ts` with `toCanonicalStatus(oneStatus)` covering every status the ONE mock emits, mapping to the canonical enum.
3. Write `mapTracking.ts` turning ONE T&T events into `NormalizedEvent[]` with a stable `dedupeKey` (ONE event id when present, else a hash).
4. Write `index.ts` implementing `CarrierAdapter` (`code: 'ONEY'`, `transport: 'REST'`, capabilities) with the four methods calling `ctx.http.request(...)` against the ONE paths and returning `AdapterResult` — classifying non-2xx into `AdapterError` categories.
5. Write `one.contract.test.ts` booting the ONE mock and running `runContractSuite(new OneAdapter(), ctxFactory)`.
6. Add `apps/booking/src/adapters/one/README.md` listing endpoints, the API-key header name, rate-limit notes, and sandbox open questions.
