# Unit U-029 — Build the packages/edifact seam (translator interface + working IFTMBF reference)

## Goal

Create `packages/edifact` as a translator seam: `toEdifact` / `fromEdifact` plus a `MessageType` enum and UN/EDIFACT segment primitives, with one fully working reference — canonical ↔ IFTMBF — and stubs for the other message types.

## Context (read first)

Per spec §14 and decision D-014, no v1 carrier uses EDIFACT, but future carriers will, so the architecture keeps a seam. This package is pure functions, no I/O. `toEdifact(canonical, MessageType)` builds an interchange; `fromEdifact(raw)` returns `{ type, canonicalPartial }`. IFTMBF (firm booking request) is implemented end to end with a round-trip test; `IFTMBC`, `IFTSTA`, `CODECO` are stubs that throw `NotImplemented` with a doc comment. Booking cancellation is a message-function code on IFTMBF, not a separate message type. A future HYBRID adapter composes this package plus a future `packages/edi-transport`.

## Anchors

- packages/carrier-core/src/types.ts — CanonicalBookingRequest, the shape iftmbf.ts maps
- vault.md#Decisions D-014 — the seam-only scope

## Hard rules

- NEVER perform network, filesystem, or DB access in packages/edifact (spec §14)
- DO NOT implement IFTMBC / IFTSTA / CODECO in v1; they throw NotImplemented (constitution D-004)
- DO NOT import from apps/booking or packages/db in packages/edifact
- file packages/edifact/src/messages/iftmbf.ts MUST exist after bolt

## Implementation steps

1. Create `packages/edifact/package.json` (name `@zhenghe/edifact`) depending only on `@zhenghe/carrier-core` for the canonical types.
2. Write `types.ts` with `MessageType = 'IFTMBF' | 'IFTMBC' | 'IFTSTA' | 'CODECO' | 'CONTRL' | 'APERAK'` and the translator interfaces.
3. Write `segments.ts` with minimal UN/EDIFACT segment builders/parsers (`UNH`, `BGM`, `DTM`, `LOC`, `EQD`, `NAD`, `RFF`) — enough for IFTMBF.
4. Write `messages/iftmbf.ts` with `buildIftmbf(canonical)` and `parseIftmbf(raw)` producing/consuming a real interchange; a cancellation is expressed via the BGM message-function code.
5. Write `index.ts` exporting `toEdifact(canonical, type)` (dispatches to `buildIftmbf` for IFTMBF, throws `NotImplemented` otherwise) and `fromEdifact(raw)` (detects the message type from `UNH`, dispatches to `parseIftmbf`).
6. Write `__tests__/iftmbf.test.ts` round-tripping a canonical booking request through `toEdifact` then `fromEdifact` and asserting the core fields survive.
7. Add `README.md` stating this is a seam and that the full message set + `edi-transport` (SFTP/AS2) is a later spec.
