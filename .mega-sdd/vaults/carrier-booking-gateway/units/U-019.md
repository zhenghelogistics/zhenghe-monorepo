# Unit U-019 — Build apps/mock-carriers (scripted REST mocks for ONE, Maersk, HMM, Evergreen)

## Goal

Provide a dev/test-only HTTP app that simulates each carrier's booking REST contract: scripted ack, a time/step-driven status progression, a scripted tracking list, cancel, and error-mode injection via `x-mock-scenario`.

## Context (read first)

Per spec §11 and decision D-010, adapters are built and contract-tested against these mocks until real sandboxes arrive. One app, routes namespaced per carrier (`/one`, `/maersk`, `/hmm`, `/evergreen`); each namespace mimics the shape that carrier's adapter codes against. HMM and Evergreen use proprietary payloads, so their mocks reflect a best-guess proprietary shape that the corresponding adapter maps — this is explicitly provisional (OQ-DM-2). The mock performs a stubbed-but-present auth check so the adapter's auth wiring is exercised.

## Hard rules

- DO NOT import apps/mock-carriers from apps/booking runtime code; test/dev only
- ALWAYS reject a request missing the expected auth header/token shape with 401 in each carrier namespace
- DO NOT accept an x-mock-scenario value outside: auth-fail | validation-fail | timeout | rate-limit | carrier-500

## Implementation steps

1. Create `apps/mock-carriers/package.json` (name `@zhenghe/mock-carriers`) with a small HTTP framework and a `start` script; base URL configured per carrier via env in the adapter side.
2. Write `scenarios.ts` reading `x-mock-scenario` and producing the matching failure (401, 422, a hang beyond the client timeout, 429, 500) or `null` for the happy path.
3. Write `carriers/one.ts` and `carriers/maersk.ts` as route groups: `POST create` returns a carrier-shaped ack with a fake booking ref; `GET status/:ref` returns `RECEIVED` → `PENDING_CONFIRMATION` → `CONFIRMED` by elapsed calls or a `?advance` control; `GET tracking/:ref` returns a scripted event list; `POST cancel/:ref` flips to cancelled.
4. Write `server.ts` mounting all four namespaces (HMM and Evergreen route files are added in U-022/U-023 alongside their adapters, or stubbed here — keep `server.ts` mounting-only).
5. Add a test that boots the app and drives the ONE namespace through create → status → tracking → cancel, plus each `x-mock-scenario`.
