# Unit U-024 — Wire the adapter registry and the end-to-end mock integration test

## Goal

Populate the `AdapterRegistry` with the four real adapters, provide the composition root that assembles services + registry + worker into the running service, and add an end-to-end test that books through the HTTP API against the mock carriers and reaches `CONFIRMED` and `CANCELLED`.

## Context (read first)

Per spec §8 and flow F-C-001, this is the unit that makes the gateway whole: the registry maps `ONEY` / `MAEU` / `HDMU` / `EGLV` to the U-020..U-023 adapters, the composition root injects the `CredentialStore`, services, registry, and worker into `buildServer`, and the e2e test proves a booking created via `POST /bookings` for each carrier reaches `CONFIRMED` via worker polling against `apps/mock-carriers`, then cancels — with no carrier portal login anywhere. It also confirms `carrier_messages` rows are written with correlation ids.

## Anchors

- apps/booking/src/adapters/one/index.ts, maersk/index.ts, hmm/index.ts, evergreen/index.ts — the four adapters to register
- apps/booking/src/server.ts — buildServer
- apps/booking/test/support/app.ts — extend or mirror for the mock-carrier variant

## Hard rules

- ALWAYS key registry adapters by their exact SCAC code (ONEY, MAEU, HDMU, EGLV)
- NEVER construct the concrete services + registry for the running app outside composition.ts
- NEVER run the e2e test against a real carrier host; use apps/mock-carriers
- file apps/booking/src/adapters/index.ts MUST exist after bolt

## Implementation steps

1. Write `adapters/index.ts` exporting `buildRegistry(env)` that constructs each adapter with its base URL from `env` (pointing at the mock in test/dev) and returns the `AdapterRegistry` Map.
2. Write `composition.ts` exporting `composeApp(env)` that builds the pool, `PgCredentialStore`, domain services, the registry, and the worker, then calls `buildServer` with them; `src/index.ts` uses this.
3. Write `e2e.mock.test.ts`: start `apps/mock-carriers`; for each carrier code, `POST /bookings` → run the worker `submitBooking` + poll loop → assert `CONFIRMED`; `POST /bookings/:id/cancel` + `submitCancellation` → assert `CANCELLED`; assert `carrier_messages` has rows with `correlation_id` set and no secret material.
