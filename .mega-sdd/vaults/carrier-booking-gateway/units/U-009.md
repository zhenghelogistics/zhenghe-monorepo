# Unit U-009 — Build the ContractTestKit (standard create -> status -> tracking -> cancel suite)

## Goal

Provide `runContractSuite(adapter, { baseUrl })` — a reusable suite that drives any `CarrierAdapter` through create, poll-to-CONFIRMED, tracking, and cancel, asserting the canonical output shapes and that `toCanonicalStatus` covers every state the target emits.

## Context (read first)

Per spec §8 and §12, every adapter ships a contract test that runs against its mock now and can be re-pointed at a real sandbox later. This kit is the shared body of that test: it feeds a canonical booking request through the adapter, loops `getBookingStatus` until the mapped status is terminal, calls `getTracking`, then `cancelBooking`, checking each result validates against the carrier-core zod schemas and status enum.

## Anchors

- packages/carrier-core/src/adapter.ts — CarrierAdapter surface the kit exercises
- packages/carrier-core/src/schemas.ts — schemas the kit validates adapter output against
- packages/carrier-core/src/status.ts — the enum toCanonicalStatus must land in

## Hard rules

- ALWAYS assert every AdapterResult is ok with schema-valid data or a classified AdapterError
- NEVER hardcode a carrier-specific field name in the kit; work only through the CarrierAdapter surface
- file packages/carrier-core/src/testing/contractKit.ts MUST exist after bolt

## Implementation steps

1. Write `fixtures.ts` with a valid `CanonicalBookingRequest` fixture (FCL, two commodities, two equipment) and a `TrackingQuery` fixture.
2. Write `contractKit.ts` exporting `runContractSuite(adapter, ctxFactory)` that: calls `createBooking`, asserts an `ok` result with a `BookingAck`; polls `getBookingStatus` with a bounded loop until `toCanonicalStatus` yields `CONFIRMED` or `DECLINED`; calls `getTracking` and asserts an array of schema-valid `NormalizedEvent`; calls `cancelBooking` and asserts a `CancelAck` or a `NOT_FOUND`/`VALIDATION` error depending on state.
3. Also assert `toCanonicalStatus` returns a valid enum member for every distinct raw status string seen during the poll loop.
4. Write `contractKit.test.ts` running the suite against a tiny in-file fake adapter to prove the kit itself is sound.
