# Unit U-027 — Build the Booking detail screen (tabs, cancel, refresh)

## Goal

Implement the Booking detail screen: header with status chip and key fields, tabs for Overview / Timeline / Tracking / Carrier messages (admin only), and Cancel + Refresh actions.

## Context (read first)

Per spec §15 and flow F-U-002. The screen polls `getBooking(id)` via TanStack Query, renders the canonical request under Overview, the `booking_events` timeline under Timeline, `shipment_events` grouped by equipment under Tracking, and the raw `carrier_messages` under an admin-only tab. Cancel is shown only when the status is in the cancelable set and the carrier's `capabilities.supportsCancel` is true; it calls `cancelBooking(id, reason)`. Refresh calls `refreshBooking(id)`. Parked states (`SUBMISSION_FAILED` / `CANCELLATION_FAILED`) render prominently.

## Anchors

- apps/booking/web/src/lib/apiClient.ts — getBooking, getBookingEvents, getBookingTracking, cancelBooking, refreshBooking
- flows.md#F-U-002 — the cancel flow and its guard
- vault.md#Architecture — the booking-detail tabs list

## Hard rules

- NEVER derive status in StatusChip; render the API `status` verbatim (constitution C-003)
- NEVER show the Carrier messages tab to a non-admin role
- DO NOT enable Cancel unless the status is in the cancelable set AND the carrier supports cancel
- file:apps/booking/web/src/**/*.tsx MUST follow PascalCase naming for component files

## Implementation steps

1. Write `components/StatusChip.tsx` mapping each `CanonicalBookingStatus` to a label + tone (ok / warn / crit), rendering the raw enum as the source of truth.
2. Write `components/EventTimeline.tsx` rendering an ordered `booking_events` list with from→to status, source, actor, and timestamp (displayed in `Asia/Singapore`).
3. Write `screens/BookingDetail.tsx` — header + tabbed body; wire Cancel (guarded) and Refresh; surface `SUBMISSION_FAILED` / `CANCELLATION_FAILED` with the carrier error message from the latest ERROR event.
4. Write `screens/bookingDetail.test.tsx` — with a mocked client: tabs switch and render their data; Cancel is disabled for a `DRAFT` booking and for a non-cancel-capable carrier; the Carrier messages tab is hidden for a `controller` token.
