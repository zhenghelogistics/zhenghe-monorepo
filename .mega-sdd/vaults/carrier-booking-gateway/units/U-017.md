# Unit U-017 — Implement /carriers, /tracking, and the full /health routes

## Goal

Expose `GET /tracking`, `GET /carriers` (registry + capabilities + credential health), `PUT /carriers/:code/credentials` (admin), and finish `GET /health` so it reports DB, worker heartbeat, and per-carrier circuit state.

## Context (read first)

Per spec §7, §13, §16. `GET /carriers` joins the `carriers` registry with `CredentialStore.list()` health and the circuit-breaker state, never exposing secret material. `PUT /carriers/:code/credentials` is `admin`-only and calls `CredentialStore.put`. `GET /health` fills in the real checks the U-002 stub left as placeholders: a `SELECT 1`, the graphile-worker heartbeat, and `circuitBreaker.state(code)` per carrier.

## Anchors

- apps/booking/src/api/health.ts — the stub route from U-002 to extend (keep the response shape)
- apps/booking/src/domain/credentialStore.ts — list(), put()
- packages/carrier-core/src/http/circuitBreaker.ts — state(key) for /health and /carriers
- apps/booking/src/domain/trackingService.ts — queryEvents for GET /tracking

## Hard rules

- ALWAYS gate PUT /carriers/:code/credentials with requireRole('admin') (constitution B-004)
- NEVER return secret material from GET /carriers; only configured / lastAuthOk / circuitState (constitution B-002)
- ALWAYS validate route input with a zod schema at the boundary (constitution A-003)
- file apps/booking/src/api/health.ts MUST exist after bolt

## Implementation steps

1. Write `tracking.ts` registering `GET /tracking` with the query-schema from `trackingService.queryEvents`, `requireRole('viewer')`, returning `{ items, page, pageSize, total }`.
2. Write `carriers.ts` registering `GET /carriers` (`viewer`) that returns each carrier's `{ code, displayName, transportMode, capabilities, enabled, credential: { configured, lastAuthOk, circuitState } }`, and `PUT /carriers/:code/credentials` (`admin`) validating `{ authType, secret, baseUrl, accountRef? }` and calling `CredentialStore.put`, returning `204`.
3. Modify `health.ts` to run a DB `SELECT 1`, read the worker heartbeat row/metric, and gather `circuitBreaker.state(code)` + `lastAuthOk` per carrier; return `200` when DB is reachable, `503` otherwise, keeping the `{ db, worker, carriers }` shape.
4. Write `carriers.test.ts` with Fastify `inject`: `GET /carriers` never contains a secret field; `PUT` as `viewer` → 403, as `admin` → 204; `GET /health` returns the three sections.
