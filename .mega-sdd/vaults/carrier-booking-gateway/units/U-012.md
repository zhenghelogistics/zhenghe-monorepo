# Unit U-012 — Implement bookingService and trackingService (create, cancel guard, refresh, reads)

## Goal

Implement the domain services the API calls: create a booking (insert `PENDING_SUBMISSION`, append a NOTE event, enqueue `submit_booking`), guard and request a cancel, enqueue a refresh, and read a booking with its events and tracking.

## Context (read first)

Per spec §7 and §9, and flows F-U-001 / F-U-002 / F-U-003. `bookingService.createBooking` validates the canonical request against the carrier-core zod schema, denormalizes `pol`/`pod`/`vessel`/`voyage`/`etd`/`customerRef` onto the row, honours the `Idempotency-Key` uniqueness, and enqueues the submit job. `cancelBooking` checks the status is in the cancelable set and the carrier's `capabilities.supportsCancel` before calling `reconcile(..., CANCELLATION_REQUESTED)` and enqueuing `submit_cancellation`. `trackingService` is read-only over `shipment_events`.

## Anchors

- apps/booking/src/domain/statusReconciler.ts — reconcile, recordError
- packages/carrier-core/src/status.ts — the cancelable set constant
- apps/booking/src/db/rowTypes.ts — BookingRow, ShipmentEventRow

## Hard rules

- ALWAYS validate the payload with canonicalBookingRequestSchema before any write in createBooking (constitution A-003)
- NEVER UPDATE bookings.status directly from bookingService; go through reconcile (constitution C-002)
- NEVER call a carrier adapter directly from bookingService; only enqueue jobs (constitution D-001)
- ALWAYS enqueue onto the same job queue the worker (U-013) consumes

## Implementation steps

1. Write `bookingService.ts` with `createBooking(input, actor, idempotencyKey?)`: parse with the schema, short-circuit-return an existing row when `(actor, idempotencyKey)` already exists, otherwise insert `bookings` with `status = PENDING_SUBMISSION` and the denormalized columns, `appendEvent` a `NOTE`, enqueue `submit_booking(bookingId)`, return the row.
2. Add `requestCancel(bookingId, actor, reason?)`: load the booking + its carrier capabilities; reject when status is not in the cancelable set or `supportsCancel` is false; else `reconcile(bookingId, CANCELLATION_REQUESTED, 'user', actor)` and enqueue `submit_cancellation(bookingId)`.
3. Add `requestRefresh(bookingId)`: enqueue `poll_booking_status` and, when the booking is `CONFIRMED`, `poll_tracking`.
4. Add `getBookingDetail(bookingId)` returning the row + ordered `booking_events` + `shipment_events`.
5. Write `trackingService.ts` with `queryEvents({ equipmentRef?, carrier?, dateFrom?, dateTo?, page, pageSize })` over `shipment_events`.
6. Write `bookingService.test.ts` against a test Postgres: create inserts one row + one NOTE + one enqueued job; a repeated idempotency key returns the first row and enqueues nothing; a cancel on a `DRAFT` booking is rejected; a cancel on a `CONFIRMED` booking with a cancel-capable carrier enqueues `submit_cancellation`.
