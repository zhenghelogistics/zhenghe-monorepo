# Unit U-005 — carrier-core canonical types, zod schemas, and the status transition table

## Goal

Define the carrier-neutral core: `CanonicalBookingRequest` (+ zod schema), the `CanonicalBookingStatus` enum with its allowed-transition table, `NormalizedEvent`, `AdapterResult` / `AdapterError`, `BookingAck` / `CancelAck`, and `CarrierCapabilities`.

## Context (read first)

First unit of `packages/carrier-core`. Per spec §5 and §8, this is the shared vocabulary every adapter, the domain layer, and the frontend speak. The canonical booking request is the trimmed DCSA Booking 2.0 subset listed in `model.md` (bookingParty, parties, commodities[], requestedEquipments[], transport, references[], flags). The status enum and its transition table are load-bearing: `statusReconciler` (U-011) is the only writer and it enforces this table. Nothing here does I/O.

## Hard rules

- DO NOT import from apps/booking or packages/db in packages/carrier-core (constitution C-001)
- DO NOT re-declare the canonical booking request schema; import it from packages/carrier-core (constitution A-003)
- file:packages/carrier-core/src/*.ts MUST follow camelCase naming

## Implementation steps

1. Create `packages/carrier-core/package.json` (name `@zhenghe/carrier-core`) depending only on zod.
2. Write `types.ts` with `CanonicalBookingRequest`, `NormalizedEvent`, `CarrierCapabilities`, `AdapterResult<T>` (discriminated union `{ ok: true, data, raw }` | `{ ok: false, error, retryable, raw? }`), `AdapterError` (with the closed `category` union `AUTH | VALIDATION | NOT_FOUND | RATE_LIMIT | CARRIER_UNAVAILABLE | TIMEOUT | UNKNOWN`), `BookingAck`, `CancelAck`, `BookingStatusView`, `TrackingQuery`.
3. Write `status.ts` exporting `CanonicalBookingStatus` (the eleven values in `model.md`) and `ALLOWED_TRANSITIONS: Record<CanonicalBookingStatus, CanonicalBookingStatus[]>` plus `isAllowedTransition(from, to)`; encode the active set and cancelable set as named constants.
4. Write `schemas.ts` with the zod schema for `CanonicalBookingRequest` matching `types.ts` exactly, exported alongside an inferred type check.
5. Re-export everything from `index.ts`; add unit tests asserting a few legal and illegal transitions and that a representative canonical request round-trips through the zod schema.
