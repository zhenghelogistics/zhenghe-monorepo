# Unit U-010 — Implement CredentialStore + PgCredentialStore (encrypted carrier secrets)

## Goal

Implement the `CredentialStore` interface (`get` / `put` / `rotate` / `list`) and its Postgres-backed implementation, encrypting secrets at rest with libsodium `crypto_secretbox` and appending `credential_events` rows.

## Context (read first)

Per spec §13 and decision D-007: per-carrier secrets live encrypted in `carrier_credentials`, the master key comes from `CARRIER_CRED_MASTER_KEY`, and `key_version` supports master-key rotation. `get()` decrypts only in memory and returns the `ResolvedCredential` shape the adapter context uses; it must never log plaintext. `list()` returns health rows (`configured`, `lastAuthOk`, without secret material) for `GET /carriers`.

## Anchors

- apps/booking/src/db/rowTypes.ts — CarrierCredentialRow, CredentialEventRow
- packages/carrier-core/src/context.ts — ResolvedCredential
- apps/booking/src/config/env.ts — CARRIER_CRED_MASTER_KEY

## Hard rules

- DO NOT write bespoke crypto; use libsodium crypto_secretbox for the secret blob (constitution B-001)
- NEVER write a decrypted secret to a log or to carrier_messages (constitution B-002)
- ALWAYS append a credential_events row with the actor on put / rotate / disable (constitution F-002)
- NEVER leave more than one active carrier_credentials row per carrier; the partial unique index enforces it

## Implementation steps

1. Write `crypto.ts` wrapping the chosen libsodium binding: `sealSecret(json, masterKey) -> { ciphertext, keyVersion }` and `openSecret(ciphertext, masterKey, keyVersion) -> json`, with the nonce packed into the stored bytea.
2. Write `credentialStore.ts` defining the `CredentialStore` interface and `PgCredentialStore(pool, env)`: `get(carrierCode, accountRef?)` loads the active row, decrypts, returns `ResolvedCredential` (auth_type + fields + base_url); `put(input)` upserts and flips `is_active`, appends `credential_events`; `rotate(carrierCode)` re-encrypts under the current master key, bumps `key_version`, sets `rotated_at`; `list()` returns non-secret health rows.
3. Write `credentialStore.test.ts` against a real test Postgres: put then get round-trips a secret; a second put deactivates the first (index holds); rotate changes `key_version` and still decrypts; `list()` never returns ciphertext or plaintext.
